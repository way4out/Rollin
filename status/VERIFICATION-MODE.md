# StellarNet Verification Mode

## GREEN — StellarNet Verified
GREEN means the application artifact is deployed from the StellarNet-controlled Rollin repository, has a published commit and verified live deployment, carries integrity evidence, and makes only rights claims actually held or authorized by StellarNet LLC.

## BLUE — External Authority Verified
BLUE is reserved for a status independently confirmed by the relevant authoritative registry or standards body.

## YELLOW — External Process Pending
YELLOW means an external authority must still accept, register, delegate, or otherwise approve the status.

## RED — Unverified
RED means the claim lacks authenticated deployment or authoritative evidence.

## Unbounded logical capacity
OEQL uses hierarchical identifiers, cursor pagination, deterministic identifiers, versioning, signed authorization records, and revocation state. "Unbounded" describes logical namespace expansion; it does not claim infinite records are physically materialized.

## Authority boundary
This verification layer can provide stronger cryptographic application evidence, but it cannot replace IANA, ICANN, DNS root, trademark, statutory, court, or other external authority.

## Verification record
controller, canonical identifier, namespace, commit, deployment ID, deployment state, specification version, issued-at, renewal/expiry, revocation, SHA-256 hash, evidence, and authority class.
