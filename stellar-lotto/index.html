Winner & secure settlement

The draw is capacity-driven, not time-driven. When the configured pool reaches 100%, entry closes, the ticket set is finalized, and only then can an independently verifiable random process select the winner.

Anti-tamper gates

1. Pool finalizedNo entries accepted after close
2. Ticket snapshotImmutable draw input commitment
3. Randomness proofIndependent verifiable source
4. Winner proofWinner derived from snapshot + randomness
5. Single-release guardOnchain state must be UNPAID → PAID exactly once
6. Recipient lockFunds can only target the recorded winner

“Quantum” is used here as a design goal, not a claim that ordinary web code is quantum-secure. A real production deployment should use audited smart contracts, a verifiable randomness oracle, replay protection, reentrancy protection, pull-based claims and an explicit one-time payout state.

Rules & safeguards

Stellar Lotto is not offering a real-money lottery through this demo. Any production launch must be operated only where legally authorized. Jurisdiction, age, identity, responsible-play and sanctions controls must be enforced before paid play. Smart contracts should be independently audited before holding customer funds.
